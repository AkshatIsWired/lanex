# LanEx Windows test build (2026-10-25)

A test build for the people who tried the 2026-10-05 build. It fixes every
problem reported since then and carries the hardened installer from the Ship
line. Please install it over the old one (your projects are kept) and tell us
what still goes wrong.

## Install

1. Download **LanEx-Setup.exe** below (SHA-256 `592100e248fd66edc89700a4084d3726958460fe526df6d132882b0fdab37e8f`).
2. Run it. Windows says "Windows protected your PC" because the installer is
   not code-signed yet: click **More info**, then **Run anyway**.
3. Welcome, License, Configure (**Recommended** is right for a first chip),
   **Install**. If WSL is not on yet, Windows asks for administrator permission
   and restarts once; Setup opens again by itself after you sign in.
4. On "Ready to design", click **Finish**. LanEx opens.

Already have the 2026-10-05 build? Just run the new Setup: it upgrades in place
in a few minutes and keeps your projects, runs and PDKs.

Requirements: Windows 11, or Windows 10 22H2 with its updates; x64; 8 GB of
memory recommended; about 23 GB free on C:.

## Fixed since the 2026-10-05 build

### Reported by testers

- **LanEx no longer dies when the laptop sleeps.** After sleep or a long idle,
  the window showed "127.0.0.1 refused to connect". The launcher took the
  dropped connection for a closed window and shut LanEx down. Now an open
  window keeps LanEx running through sleep, Wi-Fi drops and a hidden window;
  LanEx restarts itself if its server stops, and reopens the window if needed.
  Unsaved edits in the RTL IDE are kept as you type and offered back if the
  window is ever lost.
- **Runs no longer disappear** from Runs, Layout and Analytics. Listing the
  runs of a project took 20 to 30 seconds with a dozen runs, so the page timed
  out and showed "no runs" until a later try worked. It now takes a fraction of
  a second, and a slow moment keeps the list on screen instead of emptying it.
  Pages also load faster.
- **The PDK you pick is the PDK the run uses.** Picking gf180 for Blinky used
  to fail with "sky130A not found" because the project's config still said
  sky130A. The PDK picker now follows the project's config and saves your
  choice to it (with Undo); a run whose picker and config disagree is stopped
  with both named and a one-click fix. New projects start on a PDK that is
  installed, with its usual cell library.
- **Starter projects reach a clean GDS on gf180mcuD and ihp-sg13g2**, not only
  sky130 (checked with real runs: Blinky, FIFO, Multiplier and Counter).
- **Every value shows where it came from again.** Each setting on Setup and
  each number on Verify and Analytics has a small source button that opens the
  exact file at the line with the value highlighted, as the old build did.
- **Layout and 3D work on every PDK.** gf180mcu (all variants) and ihp-sg13g2
  now have real layer heights in 3D; gf180 layers are named and stacked
  correctly; IHP's active layer is no longer missing. LanEx ships its own
  process files, so 3D no longer depends on the GDS3D download.
- **3D is a button you can see**: "3D view", next to "Open in KLayout".
- **Desktop viewers (KLayout, OpenROAD, Magic) open as real windows** from
  every place LanEx starts them, including the command console (the "COPY
  MODE" taskbar-only window).
- **Cancel in Setup works** (no more Task Manager): it asks first, keeps what
  was downloaded, and running Setup again continues from there. A stopped
  install no longer looks finished; LanEx tells you to run Setup again.
- **Setup no longer stalls at 80 %** on a slow or dropped connection:
  downloads resume where they stopped and show their real progress.

### The installer itself (Ship line)

- Survives a restart, a dropped connection, a closed window or sleep; every
  download resumes and is SHA-256 checked; a partial or corrupt file is never
  used.
- Every dependency is pinned: Ubuntu packages from a dated snapshot, Python
  packages from a hash-locked list, the LibreLane image by digest, the Ubuntu
  image and every PDK file by SHA-256, from LanEx's own mirror first.
- Stops early, with the reason and the next step, when Windows is too old or
  there isn't enough memory or disk.
- Uninstall keeps your work by default and says what it kept.
- Every error names its log: `%LOCALAPPDATA%\LanEx\logs\install.log`.

## Please try

1. Install or upgrade, open LanEx, run Blinky on sky130A.
2. Install gf180 or IHP (Tools), switch the PDK on Setup, run again.
3. Open Layout, click **3D view**.
4. Leave LanEx open, close the laptop lid, wake it after a while: LanEx should
   still be there.
5. Click a source button next to any number on Verify or Analytics.

## If it goes wrong

Open an issue with the **Windows install problem** form and attach
`%LOCALAPPDATA%\LanEx\logs\install.log` and
`%LOCALAPPDATA%\LanEx\logs\launcher.log` (paste the path into Explorer's
address bar).

## Known limits

- Not code-signed yet.
- Real laptop sleep could not be reproduced in our test VMs; the fix was
  tested with an abrupt window loss (what sleep looks like to LanEx) and unit
  tests of the sleep rules. Tell us if LanEx is gone after waking.
- LanEx is not a sign-off tool: "Clean" covers LibreLane's own checks.
